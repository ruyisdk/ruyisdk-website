## 使用说明

开始刷写前，请备份开发板上需要保留的数据。本刷写器仅支持 Chrome、 Chromium 和 Edge，依托 WebUSB 最大程度还原 ruyi 包管理器镜像刷写程序的功能，但受限于浏览器沙箱环境只支持 fastboot 模式进行镜像刷写，且无法自动下载资源，需要点击链接手动下载资源后再手动选择每个已经下载完成的文件。大部分受支持的开发板在刷写过程中会重启，重启后设备 USB VID/PID 会改变，也需要重新选择对应的设备授权。

1. **选择开发板和系统**：在终端输入对应的编号并按回车，依次选择开发板、硬件版本和系统镜像。遇到 `(y/N)` 时，检查终端输出是否符合预期，如要继续则输入 `y`。
2. **准备镜像**：由于跨域的限制，文件大概率无法自动下载，但仍能实现自动解包和刷写。先点击“选择目录”选择用于存放下载文件和解包后文件的路径，网页会尝试自动下载。自动下载失败以后才会在侧栏显示文件链接，用于手动下载，手动下载完成后手动导入已下载的文件授权读取。所有文件授权读取后，向导会校验 SHA-256，把刷写用的文件解包到所选目录的 `RuyiImages/` 下。
3. **启动刷写流程**：按开发板文档进入刷写模式，用支持数据传输的 USB 线连接电脑，然后点击“连接开发板”。在侧栏核对设备名称、USB VID/PID 等信息。确认目标和刷写步骤后再开始写入。
4. **刷写流程中的重新授权**：大部分开发板在刷写过程中会重启，由于 USB VID/PID 改变，需要重新授权，此时向导会一直等待设备连接。此时不要重启向导，保持 USB 线连接，再次点击“连接开发板”，选择同一块物理板。授权完成后向导将自动完成后续流程。

### 没有看到 USB 设备

能看到 USB 设备并不意味着当前用户有足够的权限执行刷写。

- **Linux**：用 `lsusb` 能看到 USB ID，但是只有 `sudo fastboot devices` 能列出开发板，普通用户 ``fastboot devices`` 不能。请按发行版或开发板文档配置相应的 udev 规则，让桌面用户拥有读写权限。重载规则并重新连接后，用普通用户运行 `fastboot devices` 确认。
- **Windows**：在设备管理器中找到当前阶段的 USB 接口，核对硬件 ID 和驱动状态。若驱动缺失或不兼容，请按厂商说明为该接口配置支持 WinUSB 的驱动。
- **macOS**：待进一步验证。

遇到问题时，展开侧栏底部的“刷写日志”查看失败的步骤。
