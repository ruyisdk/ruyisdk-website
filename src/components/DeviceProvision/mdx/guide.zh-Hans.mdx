## 使用说明

开始刷写前，请备份开发板上需要保留的数据。

1. **选择系统。** 在终端输入选项编号并按回车，依次选择开发板、硬件版本和系统镜像。遇到 `(y/N)` 时，输入 `y` 继续。
2. **准备镜像。** 点击“选择目录”。向导会校验 SHA-256，把刷写用的文件解包到所选目录的 `RuyiImages/` 下。如果提示手动导入，请选择与提示文件名完全一致的本地文件。需要下载时，可使用侧栏提供的镜像链接。

### 通过 Fastboot 刷写开发板

在桌面 Chrome 或 Edge 中打开本页。按开发板文档进入刷写模式，用支持数据传输的 USB 线连接电脑，然后点击“连接开发板”。在侧栏核对设备名称、USB 厂商和产品 ID，以及设备提供的序列号。确认目标和刷写步骤后再开始写入。

部分流程会重启开发板。保持 USB 线连接；设备重新出现时，名称或 USB ID 可能变化。如果向导仍在等待重连，再次点击“连接开发板”，选择同一块物理板当前显示的设备。按提示确认后，向导会从中断处继续，无需点击“重新开始”。

### 可以看到 USB 设备，但连接失败

先关闭可能占用该设备的其他刷写工具或网页。若浏览器已配对但仍提示 `Access denied`，请检查操作系统对当前 USB 接口的访问权限：

- **Linux：** 如果只有 `sudo fastboot devices` 能列出开发板，用 `lsusb` 查看当前阶段的 USB ID。按发行版或开发板文档配置相应的 udev 规则，让桌面用户拥有读写权限。重载规则并重新连接后，用普通用户运行 `fastboot devices` 确认。
- **Windows：** 在设备管理器中找到当前阶段的 USB 接口，核对硬件 ID 和驱动状态。若驱动缺失或不兼容，请按厂商说明为该接口配置支持 WinUSB 的驱动。
- **macOS：** 在“系统信息 → USB”中检查当前阶段的设备是否出现。如果系统能看到设备，但 Chrome 无法连接，可在 `chrome://device-log` 查看此次连接的错误。

遇到问题时，展开侧栏底部的“刷写日志”查看失败的步骤。
